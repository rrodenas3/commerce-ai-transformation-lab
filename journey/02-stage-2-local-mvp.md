# Journey 02 — from a working slice to a controlled evaluation

## What changed

Stage 2 moves the project from a single golden development case toward a reconstructable comparison. The work is deliberately sequenced so a failure changes the design before confirmatory results exist.

The first ranked development failure was foundational: the preserved base did not contain an outer evaluation authority. A process running from a different directory could not prove that private oracle material, repository history, home files, network, or subprocess capability were unavailable. The project recorded that failure, rejected self-authored isolation claims, and introduced an outer-only container launcher, a single read-only input bind, an isolated temporary workspace, framed stdout export, outer materialization, attestation, output seal, and one-way oracle release.

## Raul's transformation decisions

Raul remains the accountable evidence and transformation owner. AI assisted requirements analysis, adversarial review, implementation, testing, and recorded candidate acquisition. The consequential decisions represented in the repository are:

1. Preserve the failed development trace rather than rewriting it as a successful test.
2. Rank failures before execution and adapt to the highest-ranked unresolved failure.
3. Keep the oracle and family mapping outside the runtime mount.
4. Require complete recorded attempt accounting; a deterministic fixture cannot become canonical AI evidence.
5. Bind the evaluation to a clean source commit, tree, exported bytes, exact minimal runtime build context, immutable image receipt, cases, schedules, policy, workflow, adapter, provider, clock, thresholds, and exact-zero controls.
6. Make output freezing precede oracle release through atomic file-per-state records; persist any raw exact-zero failure as terminal invalidation.
7. Count safe routing separately from verified remedy.
8. Preserve any post-oracle fix only as regression evidence and require a new pack for another confirmatory claim.

The first restricted acquisition also produced a useful failure before confirmatory execution. Thirty-four candidate-bearing outputs looked natural but none satisfied the actual bounded parser because the V1 brief omitted its exact enums, field schema, and source-citation vocabulary. Raul preserved the aggregate failure and private-ledger digest, rejected mechanical translation as evidence laundering, and required a new oracle-free V2 acquisition identity with an explicit machine contract.

The first confirmatory pack itself then failed a pre-run disclosure review: its public, runtime-mounted manifest named the 12 coverage families. No container run, oracle release, or score existed, and the private oracle and nonce remained unopened. The team preserved that governance event, invalidated `S2-EVALUATION-20260811-V1`, and rolled forward to `S2-EVALUATION-20260812-V2` with anonymous public coverage aggregates and named mapping verification deferred until oracle release.

V2 then exposed a different pre-run control failure during release preparation. Its runtime-image pin had used checkout bytes, which made the same committed source non-reproducible across LF and CRLF checkouts. Preparation stopped at `not-started`; no container ran, no state advanced, no private oracle or nonce was opened, and no score was created. The team preserved V2 unchanged, recorded the failure publicly, moved runtime context construction to exact committed Git blobs with clean-tree and tree-mode gates, and rolled the confirmatory identity to `S2-EVALUATION-20260812-V3`.

V3 reached the same fail-closed boundary for a new orchestration defect: the release lock itself dirtied the module checkout, while preparation verified the pack against that checkout instead of the explicit clean source. Only the lock marker was written; state stayed `not-started`, and no container, oracle release, or score existed. The team preserved V3 unchanged, made the public manifest the minimal status-routing read, required the explicit clean source for canonical runs, rooted pack and runtime-pin verification there, and rolled forward to `S2-EVALUATION-20260812-V4`.

## What is measured

The frozen design contains 36 new synthetic cases across 12 declared families, three cases per family. The assisted driver executes the real governed U5 workspace, authority, action, adapter, verifier, unsent-communication, and closure path; the comparator replays the actual Q1-Q8 design. The separate scorer replays their raw frozen trees, compares the recorded recommendation and governed outcome with the released oracle rather than the runtime policy, conserves mutually exclusive outcomes, and reports quality, routing, approval, action, verification, communication, closure, recovery, structural work, and runtime/provider evidence separately.

These are synthetic system observations. They are not observed human review burden, adoption, trust, customer recovery, delivery, satisfaction, retained revenue, savings, or realised business value.

## What remains before local-MVP evidence

The source and development adaptation must first be committed. A fresh restricted acquisition must then produce all 36 recorded attempt outcomes from oracle-free inputs. Only after a clean source binding and real least-privilege Docker run may the project freeze outputs, verify eligibility, release the oracle, and score.

If any critical control fails, the result is `stop`. If evidence is incomplete or exposed, it is `pause`. A positive aggregate cannot override either boundary. Until all gates pass, maturity remains `foundation`.
